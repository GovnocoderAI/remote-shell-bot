# remoteBot

RemoteShellBot — средство удалённой поддержки с явным согласием владельца машины.
Оператор подключается через Telegram, хост-машина подтверждает каждое подключение
локально и видит каждую команду и каждый снимок экрана в реальном времени.

Проект решает одну задачу: дать администратору удалённый shell и снимки экрана,
не превращаясь в скрытый агент. На хосте нет фонового перехвата ввода, нет
скрытых снимков и нет невидимых сессий.

## Возможности

- Удалённый shell с сохранением рабочего каталога в рамках сессии.
- Снимок экрана только при включённом праве: хост разрешает его при
  подтверждении конкретного подключения.
- Локальная панель хоста под паролем: входящие запросы, активные сессии,
  журнал команд, просмотр отправленных снимков, отзыв сессии и прав.
- Права операторов и политика устройства сохраняются между перезапусками
  и видны владельцу машины.
- Права активной сессии можно сократить в один клик; снимок экрана отзывается
  отдельно и действует только до конца сессии.
- Telegram-бот: список устройств, подключение, выполнение команд, снимки,
  журнал аудита, отзыв устройств.
- Аутентификация оператора: заявка на доступ, allow-list, TOTP.
- Новый пользователь видит описание продукта и кнопку запроса доступа.
- Бот выдаёт готовые команды установки под Windows и Linux/macOS.
- Одноразовые enrollment-токены с коротким сроком жизни.
- Одноразовая учётная запись на каждую сессию с TTL.
- Полный журнал аудита на сервере и локальный журнал на хосте.
- Кроссплатформенность: Windows, Linux, macOS.
- Устойчивое подключение: прямое, через настроенный прокси, публичные списки
  прокси с GitHub и WireGuard по явному флагу.
- Консольный клиент `rsb console`: shell, аудит, одноразовые и live-снимки
  экрана с ANSI-предпросмотром.
- Live-просмотр экрана только при выданном праве и активной сессии.
- Диагностика сети: `rsb netcheck`.

## Чего в проекте нет

- Перехвата ввода и кейлоггера.
- Скрытой работы: агент всегда виден в списке процессов и в локальной панели.
- Снимков экрана без активной сессии.
- Передачи файлов и интерактивного TUI в текущей версии.
- Захвата экрана без графической сессии: в Wayland снимок может быть
  недоступен по решению композитора.

## Архитектура

```
                    Telegram
                       |
              +--------v---------+
              |  rsb server      |   VPS, WSS + HTTPS
              |  bot + relay     |
              |  SQLite + audit  |
              +--------^---------+
                       |  исходящее соединение
                       |  HMAC-рукопожатие
              +--------+---------+
              |  rsb agent       |   машина пользователя
              |  executor        |
              |  local UI :8765  |
              +------------------+
```

Сервер не имеет доступа к машине, пока агент сам не установит исходящее
соединение. Входящие порты на машине пользователя не открываются.

Подробности: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md),
[docs/SECURITY.md](docs/SECURITY.md), [docs/PROTOCOL.md](docs/PROTOCOL.md),
[docs/OPERATIONS.md](docs/OPERATIONS.md), [docs/NETWORKING.md](docs/NETWORKING.md),
[docs/CONSOLE.md](docs/CONSOLE.md).

## Быстрый старт

### Сервер

```bash
python -m venv .venv
. .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env
```

Заполните `.env`:

- `RSB_BOT_TOKEN` — токен от @BotFather.
- `RSB_ADMIN_IDS` — Telegram ID операторов через запятую.
- `RSB_SECRET_KEY` — 32+ байта случайных данных в base64 или hex; при
  отсутствии ключ будет создан в `RSB_DATA_DIR/secret.key`.
- `RSB_PUBLIC_URL` — внешний адрес relay, например `wss://support.example.com`.

Запуск:

```bash
rsb server
```

Контейнер:

```bash
cp .env.example .env
# заполнить .env
docker compose up -d --build
docker compose logs -f relay
```

Контейнер слушает `127.0.0.1:8080`; TLS завершает reverse proxy на хосте.

Локальная консоль оператора:

```bash
rsb console
```

Для неё нужен `RSB_CONSOLE_TOKEN` в `.env` сервера.
Данные и SQLite лежат в томе `rsb-data`.

### Enrollment и агент

Оператор в боте выполняет `/enroll`, получает одноразовый токен и команду.
На машине пользователя:

```bash
curl -fsSL https://raw.githubusercontent.com/GovnocoderAI/remote-shell-bot/main/install.py -o install.py
python install.py --relay wss://support.example.com --token <TOKEN> --name office-pc
```

Установщик запросит пароль хоста. В неинтерактивном режиме пароль
генерируется и выводится один раз.

Установщик создаёт изолированное окружение, ставит пакет, регистрирует агент
и настраивает автозапуск. Локальная панель:

```
http://127.0.0.1:8765/?token=<UI_TOKEN>
```

`UI_TOKEN` выводится установщиком и хранится в `agent.json`.

## Использование

1. Новый пользователь: `/start` и заявка на доступ. Администратор одобряет её
   через `/requests` или `rsb operator approve <id>`.
2. Оператор: `/start`, затем `/verify <код>`.
3. `/devices` — выбрать машину и запросить права: только shell или shell и
   снимок экрана.
4. Владелец машины вводит пароль хоста в локальной панели и подтверждает
   запрос, при необходимости сокращая набор прав.
5. Оператор отправляет команды обычными сообщениями.
6. Кнопки сессии: снимок экрана (если право выдано), завершение.

Права, выданные оператору, сохраняются в истории доступа устройства.
Каждое новое подключение всё равно требует подтверждения владельца машины.

### Сеть и прокси

```
rsb netcheck
rsb connect
rsb connect --proxy socks5://127.0.0.1:1080
rsb connect --no-public-proxies
rsb connect --vpn --vpn-public
```

`rsb connect` сначала пробует прямое соединение, затем настроенные прокси,
переменные окружения, `proxies.txt`, кэш и публичные списки с GitHub.
Публичные списки можно отключить флагом `--no-public-proxies`.
WireGuard подключается только по явному `--vpn`, потому что требует прав
администратора. Подробности: [docs/NETWORKING.md](docs/NETWORKING.md).

Одна активная сессия на оператора. Сессия автоматически истекает по TTL,
при отключении агента и при закрытии со стороны хоста.

## Конфигурация

Все параметры сервера задаются переменными `RSB_*` или файлом `.env`.
Основные:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `RSB_BOT_TOKEN` | — | токен Telegram-бота |
| `RSB_ADMIN_IDS` | — | ID операторов через запятую |
| `RSB_SECRET_KEY` | генерируется | ключ шифрования секретов |
| `RSB_DATA_DIR` | `~/.remote-shell-bot` | каталог данных |
| `RSB_PUBLIC_URL` | `ws://127.0.0.1:8080` | внешний адрес relay |
| `RSB_SESSION_TTL_SECONDS` | `1800` | срок жизни сессии |
| `RSB_SESSION_REQUEST_TTL_SECONDS` | `180` | время на подтверждение запроса |
| `RSB_AGENT_LOCK_TIMEOUT_SECONDS` | `900` | автоблокировка панели хоста |
| `RSB_OPERATOR_AUTH_TTL_SECONDS` | `28800` | срок авторизации оператора |
| `RSB_ENROLLMENT_TTL_SECONDS` | `900` | срок жизни enrollment-токена |
| `RSB_COMMAND_TIMEOUT_SECONDS` | `120` | таймаут команды |
| `RSB_COMMAND_MAX_OUTPUT_BYTES` | `65536` | лимит вывода команды |
| `RSB_SCREENSHOT_MAX_BYTES` | `4000000` | лимит снимка экрана |
| `RSB_AGENT_UI_PORT` | `8765` | порт локальной панели |

## Безопасность

Все Telegram ID из `RSB_ADMIN_IDS` — администраторы с равными правами.
Разделения ролей в текущей версии нет; список ID и есть граница доступа.

Модель угроз и меры описаны в [docs/SECURITY.md](docs/SECURITY.md).
Кратко: WSS, HMAC-рукопожатие агента, хэширование секретов, TOTP оператора,
одноразовые токены, короткоживущие сессионные учётные записи, аудит,
локальное подтверждение и полная прозрачность на хосте.
